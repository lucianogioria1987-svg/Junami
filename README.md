Módulo de Gestión de Bajas y Estados (Junami 3.0)Este módulo ha sido rediseñado para transformar la eliminación definitiva de registros en un sistema de Gestión de Estados (Activo/Inactivo) con persistencia de datos y segregación física en silos JSON.

🚀 Funcionalidades ClaveSistema Dual de Pestañas (Tabs): Interfaz interactiva en JavaScript que permite conmutar entre los listados de Pacientes y Profesionales sin recargar la página.Gestión de Estados (Soft Delete): Los registros ya no se eliminan del sistema. Al gestionar una "Baja", el sujeto es movido al historial correspondiente, permitiendo su recuperación inmediata.Modal DRY (Don't Repeat Yourself): Un único componente modal inteligente para la confirmación de bajas, optimizando el código frontend.Sincronización de Dashboard: Los contadores (KPIs) y agendas del sistema filtran automáticamente a los usuarios inactivos en tiempo real.

📂 Arquitectura de Datos (Silos JSON)Para garantizar la escalabilidad y velocidad del sistema, hemos separado físicamente los datos operativos de los históricos:ArchivoContenidoEstadopacientes.jsonPacientes en tratamientoActivoprofesionales.jsonStaff médico operativoActivobajas_pacientes.jsonHistórico de egresosInactivobajas_profesionales.jsonHistórico de licencias/bajasInactivo🛠️ Flujo de Trabajo (QA)Baja: Al confirmar una baja, el objeto se extrae de su archivo de origen y se inserta en el silo de bajas correspondiente con su motivo.Alta (Reactivación): El sistema busca el ID en el histórico, lo remueve e inyecta nuevamente en la base de datos activa.Filtrado: El backend (Flask) asegura que los inactivos no lleguen a los templates de agendas, turnos o buscadores generales.🎨 Consistencia VisualSe eliminaron clases de bloqueo redundantes en el sidebar para garantizar que la interfaz sea idéntica en todos los módulos.Uso de Tailwind CSS para estados visuales y Lucide Icons para señalética de seguridad (candados).
